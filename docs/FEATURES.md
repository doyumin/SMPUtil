# SMPUtil 기능 정리

SMPUtil은 Paper 26.3 서버에서 플레이어들이 함께 생활할 때 필요한 기능을 제공하는 플러그인이다. 관리자 기능은 `AdminUtil`, 경제 기능은 `Econet`의 담당이며, SMPUtil은 두 플러그인에 직접 의존하지 않는다.

## 명령어

| 기능 | 영어 명령어 | 한글 별칭 |
|---|---|---|
| 한글 닉네임 | `/nick` | `/닉네임` |
| 집 이동 | `/home` | `/집` |
| 집 설정 | `/sethome` | `/집설정` |
| 집 삭제 | `/delhome` | `/집삭제` |
| 스폰 이동 | `/spawn` | `/스폰` |
| 텔레포트 요청 | `/tpa` | `/텔포` |
| 텔레포트 수락 | `/tpaccept` | `/수락` |
| 텔레포트 거절 | `/tpdeny` | `/거절` |
| 거래 | `/trade` | `/거래` |
| 도전과제 공유 | `/syncadv` | `/도전과제공유` |
| 접속자 목록 | `/players` | `/접속자` |

모든 명령어는 Paper Brigadier lifecycle의 `LifecycleEvents.COMMANDS`에서 등록된다. 플레이어 대상 인자는 실제 이름과 닉네임을 모두 인식하며, 자동완성에서는 닉네임을 먼저 보여 준다. `sender.canSee(target)`가 거짓인 투명화 플레이어는 대상 검색, 자동완성, 접속자 목록에서 제외된다.

## 한글 닉네임

### 사용법

- `/nick <닉네임|reset>`: 본인의 닉네임을 설정하거나 초기화한다.
- `/nick <플레이어> <닉네임|reset>`: 다른 접속 플레이어의 닉네임을 설정하거나 초기화한다.
- 다른 플레이어의 닉네임을 변경할 때는 실제 이름과 닉네임 모두 사용할 수 있다.
- 오프라인 플레이어의 닉네임은 변경할 수 없다.

### 규칙

- 실제 GameProfile 이름은 변경하지 않는다.
- 클라이언트로 나가는 플레이어 정보 패킷의 프로필 이름만 닉네임으로 바꾼다.
- 스킨 텍스처는 그대로 유지한다.
- 채팅에는 `displayName`, 탭 목록에는 `playerListName`을 사용한다.
- 입장·퇴장·사망 메시지의 실제 이름 조각도 닉네임으로 바꾼다.
- 기본 허용 문자는 한글 완성형, 영문, 숫자, 밑줄이다.
- 기본 길이는 1~16자다.
- 다른 플레이어의 실제 이름 또는 닉네임과 중복될 수 없다.
- 중복 비교는 대소문자를 구분하지 않는다.
- `reset`은 실제 이름 표시로 되돌린다.

닉네임은 플레이어 PDC의 다음 키에 저장된다.

| 항목 | 값 |
|---|---|
| 키 | `smputil:nickname` |
| 타입 | `PersistentDataType.STRING` |
| 키 생성 방식 | `NamespacedKey("smputil", "nickname")` |
| 키 없음 | 닉네임이 없으며 실제 이름 사용 |

닉네임 패킷 처리는 Paper 26.3의 NMS 클래스를 직접 사용한다. 패킷 처리 실패 시 패킷을 원본 그대로 보내 접속을 유지하고, 해당 플레이어의 이름표만 실제 이름으로 표시한다.

### 알려진 한계

- 한글 닉네임이 클라이언트에서 모든 이름표 상황에 정상 표시되는지는 직접 클라이언트 접속 테스트가 아직 완료되지 않았다.
- 클라이언트가 스코어보드 팀을 프로필의 실제 이름으로 찾기 때문에 닉네임 사용 플레이어에게 팀 색상이나 접두사가 적용되지 않을 수 있다.
- 바닐라 명령어의 자동완성은 닉네임을 제안할 수 있지만 서버는 실제 이름을 요구할 수 있다. SMPUtil 명령어는 실제 이름과 닉네임을 모두 처리한다.

## 집

### 명령어

- `/sethome [이름]`
- `/home [이름]`
- `/delhome <이름>`

이름을 생략하면 `home`을 사용한다.

### 동작

- 집 이름은 한글·영문·숫자·밑줄 1~16자다.
- 집 이름은 대소문자를 구분하지 않으며 저장할 때 소문자로 정규화한다.
- 기본 최대 집 개수는 플레이어당 1개다.
- 기존 집과 같은 이름으로 설정하면 위치를 변경한다.
- 집 개수 제한에 도달해도 기존 집의 위치 변경은 허용한다.
- 존재하지 않는 월드에 저장된 집으로 이동하면 오류 메시지를 표시한다.
- `home.enabled: false`이면 `/home`, `/sethome`, `/delhome`을 사용할 수 없다. 기존 저장 데이터는 삭제하지 않는다.
- 이동은 공통 `Teleporter`를 통해 `teleportAsync`로 처리한다.

집 목록은 플러그인 데이터 폴더의 `homes.yml`에 저장한다. 저장 시 임시 파일에 먼저 쓴 뒤 원자적으로 교체하여 저장 중 서버가 종료되어도 이전 파일을 보존하도록 한다.

## 스폰과 텔레포트 대기

- `/spawn`은 개인 리스폰 지점이 있으면 그곳으로 이동한다.
- 개인 리스폰 지점이 없거나 유효하지 않으면 월드 스폰으로 이동한다.
- `/spawn world`는 항상 월드 스폰으로 이동한다.
- `teleport.warmup-seconds`로 이동 대기 시간을 설정한다.
- 기본 대기 시간은 0초다.
- 대기 중 다른 블록으로 이동하면 텔레포트가 취소된다.
- 시선만 돌리는 것은 이동으로 처리하지 않는다.
- 접속 종료 시 대기 중인 텔레포트도 취소한다.
- 대기 시간이 끝나면 대상 위치를 기준으로 `teleportAsync`를 호출한다.

## 텔레포트 요청

- `/tpa <플레이어>`로 요청자가 대상에게 이동을 요청한다.
- 대상에게 클릭 가능한 `[수락]`, `[거절]` 버튼을 보낸다.
- `/tpaccept`와 `/tpdeny`로 요청을 처리할 수 있다.
- 요청은 기본 15초 후 만료된다.
- 한 대상에게 동시에 대기할 수 있는 요청은 하나다.
- 한 요청자가 보낼 수 있는 대기 요청도 하나다.
- 요청자가 다른 대상에게 새 요청을 보내면 기존 요청은 교체된다.
- 대상이 수락하는 순간의 대상 위치로 이동한다.
- 자기 자신에게는 요청할 수 없다.
- 요청자 또는 대상이 접속을 종료하면 요청을 제거하고 상대에게 알린다.
- 요청 만료는 1초마다 검사한다.

요청 상태는 `RequestBoard`에 보관한다. `Clock`을 주입하여 만료 시간을 결정하므로 요청·만료 규칙을 Bukkit 없이 테스트할 수 있다.

## 거래

### 요청

- `/trade <플레이어>`로 거래를 요청한다.
- `/trade accept` 또는 `/trade 수락`으로 수락한다.
- `/trade deny` 또는 `/trade 거절`로 거절한다.
- 거래 요청의 기본 만료 시간은 15초다.
- 이미 거래 중인 플레이어에게는 거래를 요청할 수 없다.
- 거래 대상이 보이지 않는 상태이면 수락할 수 없다.
- `trade.max-distance`가 0이면 거리 제한이 없다.
- 양수로 설정하면 같은 월드에서 해당 블록 거리 이내일 때만 거래할 수 있다.

### 거래 화면

- 두 플레이어에게 각각 별도의 거래 화면을 연다.
- 각 화면에서 왼쪽은 자신의 거래 칸, 오른쪽은 상대의 거래 칸이다.
- 자신의 거래 칸에만 아이템을 넣거나 뺄 수 있다.
- 상대의 거래 칸은 읽기 전용이다.
- 화면의 클릭·드래그 조작은 취소한 뒤 플러그인이 직접 처리한다.
- 아이템 추가·제거 등 어느 쪽 거래 내용이든 바뀌면 양쪽의 확인 상태가 해제된다.
- 두 사람이 모두 확인한 순간 아이템을 교환한다.
- 받을 인벤토리 공간이 부족하면 남은 아이템을 발밑에 떨어뜨린다.
- 거래 화면의 버튼과 복사된 아이템에는 PDC UI 태그를 붙인다.

### 종료 시 아이템 처리

| 상황 | 처리 |
|---|---|
| 양쪽 확인 완료 | 각자 상대방이 올린 아이템을 받는다 |
| 취소 버튼 또는 창 닫기 | 각자 자신의 아이템을 돌려받는다 |
| 접속 종료 | 각자 자신의 아이템을 돌려받는다 |
| 거래 중 사망 | 사망자의 아이템은 사망 위치에 드롭하고 상대는 자신의 아이템을 돌려받는다 |
| 플러그인 종료 | 닫힘 이벤트를 기다리지 않고 각자에게 아이템을 돌려준다 |

거래 아이템의 실제 상태는 `TradeSession`에만 보관한다. 거래 화면은 상태의 복사본을 렌더링하므로 창 닫힘 이벤트가 중복으로 발생해도 아이템이 중복 반환되지 않는다.

## 도전과제 공유

- `/syncadv`로 현재 공유 상태를 확인한다.
- `/syncadv on` 또는 `/도전과제공유 켜기`로 공유를 활성화한다.
- `/syncadv off` 또는 `/도전과제공유 끄기`로 공유를 비활성화한다.
- 상태 확인 권한과 토글 권한은 분리되어 있다.
- 활성화되면 접속 중인 모든 플레이어의 도전과제 세부 조건을 합집합으로 맞춘다.
- 활성화 순간 전체 동기화를 실행한다.
- 플레이어가 접속하면 전체 동기화를 실행한다.
- 누군가 세부 조건을 달성하면 해당 도전과제를 다음 틱에 동기화한다.
- `recipes/`로 시작하는 도전과제는 공유하지 않는다.
- 활성화 상태는 `state.yml`의 `advancement-sharing`에 저장한다.

## 접속자 목록

`/players` 또는 `/접속자`로 현재 접속자 목록을 확인한다.

- 닉네임이 있으면 `닉네임 (실제이름)`으로 표시한다.
- 닉네임이 없으면 실제 이름만 표시한다.
- 핑을 밀리초 단위로 표시한다.
- 투명화되어 보이지 않는 플레이어는 목록과 인원수에서 제외한다.
- `smputil.players.uuid` 권한이 있으면 UUID도 표시한다.
- UUID는 클릭하여 클립보드에 복사할 수 있다.
- 기본 정렬은 표시 이름의 소문자 기준이다.

## 권한

| 권한 | 기본값 | 용도 |
|---|---:|---|
| `smputil.nick.self` | OP | 본인 닉네임 변경 |
| `smputil.nick.others` | OP | 다른 플레이어 닉네임 변경 |
| `smputil.home` | 모두 | 집 기능 사용 |
| `smputil.spawn` | 모두 | 스폰 이동 |
| `smputil.tpa` | 모두 | 텔레포트 요청·수락·거절 |
| `smputil.trade` | 모두 | 거래 |
| `smputil.syncadv` | 모두 | 도전과제 공유 상태 확인 |
| `smputil.syncadv.toggle` | OP | 도전과제 공유 켜기·끄기 |
| `smputil.players` | 모두 | 접속자 목록 확인 |
| `smputil.players.uuid` | OP | 접속자 UUID 표시 |

## 설정

```yaml
nickname:
  min-length: 1
  max-length: 16
  allowed: "[가-힣A-Za-z0-9_]+"

home:
  enabled: true
  max-homes: 1

teleport:
  warmup-seconds: 0

tpa:
  expire-seconds: 15

trade:
  expire-seconds: 15
  max-distance: 0
```

- 설정 변경은 서버 재시작 후 반영된다.
- 설정값의 타입이나 범위가 잘못되면 기본값으로 대체하지 않고 플러그인 시작에 실패한다.
- 기존 설정 파일에 새 키가 빠져 있으면 번들 `config.yml`의 값으로 채워진다.
- 닉네임 최대 길이는 Minecraft 프로토콜 제한 때문에 16을 초과할 수 없다.

## 데이터와 상태

| 데이터 | 저장 위치 | 재시작 후 유지 |
|---|---|---:|
| 플레이어 닉네임 | 플레이어 PDC | 예 |
| 집 목록 | `homes.yml` | 예 |
| 도전과제 공유 상태 | `state.yml` | 예 |
| 텔레포트 요청 | 메모리 | 아니오 |
| 거래 상태 | 메모리 | 아니오 |
| 텔레포트 대기 | 메모리 | 아니오 |

플레이어별 데이터는 PDC에 저장하고, 여러 값의 모음은 플러그인 데이터 폴더의 YAML에 저장한다. 거래·요청·대기 상태는 서버 종료나 접속 종료 시 각 기능의 종료 처리로 정리한다.

## 테스트

Bukkit과 분리된 순수 로직을 `kotlin.test`로 테스트한다.

- `RequestBoard`: 요청 생성, 교체, 만료, 접속 종료
- `HomeBook`: 집 개수 제한, 이름 정규화, 저장·로드
- `TradeSession`: 확인, 취소, 사망, 종료 중복 방지, 아이템 총합 보존
- `missingCriteria`: 도전과제 조건 합집합
- `NicknameRules`: 길이, 허용 문자, 중복 이름
- `withShownName`: 메시지 컴포넌트의 이름 조각 치환
- `readSettings`: 설정 검증과 기본 설정

현재 테스트 명령은 다음과 같다.

```text
./gradlew test
```

## 포함하지 않는 기능

- 관리자 전용 기능: `AdminUtil` 담당
- 경제·거래 비용·텔레포트 비용: `Econet` 연동 API가 생긴 뒤 검토
- 구역 보호
- `/reload`
- `/compass`
- 옛 닉네임 방식의 `AutoQuoteListener`
