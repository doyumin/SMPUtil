# SMPUtil 설계 문서

친구들끼리 쓰는 Paper 서버의 **모든 플레이어용 생활 기능** 플러그인이다.
옛 `Utility` 플러그인을 `SMPUtil`(플레이어)과 `AdminUtil`(관리자)로 나눠 새로 만든 것이다.
코드 규칙은 루트의 `CLAUDE.md`를, 기능 규칙과 결정 이유는 이 문서를 기준으로 한다.

## 1. 범위

**들어가는 것**: 플레이어가 서로 같이 지내는 데 필요한 기능.

| 기능 | 명령어 (영어 / 한글 별칭) |
|---|---|
| 한글 닉네임 | `/nick` / `/닉네임` |
| 집 | `/home`, `/sethome`, `/delhome` / `/집`, `/집설정`, `/집삭제` |
| 스폰 | `/spawn` / `/스폰` |
| 텔레포트 요청 | `/tpa`, `/tpaccept`, `/tpdeny` / `/텔포`, `/수락`, `/거절` |
| 거래 | `/trade` / `/거래` |
| 도전과제 공유 | `/syncadv` / `/도전과제공유` (토글은 관리자만) |
| 접속자 목록 | `/players` / `/접속자` |
| 제안 | `/suggest` / `/제안` |

**들어가지 않는 것**

- 관리자 전용 기능 → `AdminUtil`
- 돈 → `Econet`. 돈이 드는 기능(텔레포트 비용, 구역 보호 등)은 Econet의 공개 API(Econet DESIGN 11장)를 거친다. 지금은 구현하지 않는다.
- 이 표에 없는 기능을 추가하려면 먼저 이 문서에 범위를 추가한다. 이름에 Util이 붙은 플러그인은 뭐든 담는 통이 되기 쉬워서다.

## 2. 공통 원칙

- **상태는 재시작해도 남는다.** 옛 Utility는 상태를 `companion object`의 리스트에 두어 재시작하면 다 풀렸다.
  - 플레이어 한 명에 딸린 값(닉네임 등) → 플레이어 PDC. 오프라인에도 플레이어 데이터 파일 안에 남는다.
  - 여러 값의 모음(집 목록, 서버 설정 토글 등) → 플러그인 데이터 폴더의 YAML.
- **아이템은 어떤 경우에도 증발하거나 복제되지 않는다.** 아이템을 옮기는 기능(거래)은 모든 종료 경로(정상 종료, 취소, 창 닫기, 접속 종료, 사망, 서버 종료)에서 아이템이 어디로 가는지 정해 둔다.
- **투명화(vanish)된 플레이어는 보이지 않는 사람으로 취급한다.** 자동완성, 접속자 목록, 텔레포트·거래 대상에서 `sender.canSee(target)`가 거짓이면 뺀다. AdminUtil의 vanish는 Bukkit `hidePlayer`를 쓰므로, 코드로 엮지 않아도 이 한 줄로 맞물린다.
- 명령어는 영어 이름 + 한글 별칭. 플레이어 인자는 **진짜 이름과 한글 닉네임을 모두** 받고, 자동완성은 닉네임을 우선 보여 준다.

## 3. 한글 닉네임

### 목표

친구들 화면에서 이름표·탭 목록·채팅·사망 메시지가 전부 한글 닉네임으로 보인다. 서버 안의 진짜 이름(GameProfile)은 영어 그대로 둔다.

### 결정과 이유

- **진짜 이름은 바꾸지 않는다.**
  - 옛 Utility는 리플렉션으로 GameProfile의 이름을 한글로 바꿨다. 그러자 바닐라 명령어(`/tp 홍길동` 등)가 이름을 읽지 못해 `AutoQuoteListener`라는 우회책이 필요했고, 버전이 바뀌면 리플렉션이 실행 중에 조용히 깨졌다. 둘 다 없앤다.
- **패킷 방식으로 한다.** 클라이언트로 나가는 플레이어 정보 패킷의 이름만 닉네임으로 바꿔치기한다. 이름표까지 바닐라와 똑같이 동작한다.
  - TextDisplay를 머리 위에 태우는 방식도 검토했지만, 웅크리기·투명화 물약·빠른 이동에서 진짜 이름표와 다르게 보여서 택하지 않았다.
- 구현 도구는 **PacketEvents** 라이브러리와 **paperweight-userdev(NMS)** 중 Paper 26.3을 지원하는 쪽을 실제로 확인해 고르고, 이유를 PR에 적는다.
  - 리플렉션으로 필드를 이름이나 타입 문자열로 찾는 방식은 쓰지 않는다. 버전이 바뀌면 컴파일 단계에서 깨져야 고칠 곳을 알 수 있다.
- 패킷의 프로필에서 **이름만** 바꾸고 스킨(텍스처 속성)은 그대로 보낸다.
- 채팅·사망 메시지는 공식 API(`displayName`, `playerListName`, 채팅 렌더러)로 처리한다. 패킷은 이름표와 탭 목록에만 쓴다.
- **확인이 필요한 것**: 클라이언트가 패킷 안의 한글·16자 초과 이름을 그대로 받아 주는지 실제 서버에서 확인한다. 거부하면 그 결과와 대안을 PR에 적고 멈춘다.
  - 16자 초과는 서버 코드에서 답이 나왔다. 프로토콜 코덱(`stringUtf8(16)`)이 서버 쪽 인코딩에서 막아 받는 사람의 접속이 끊긴다. 그래서 닉네임 최대 길이는 16을 넘을 수 없게 했다(CLAUDE.md 구현 메모).
  - 한글 16자 이내를 클라이언트가 받아 주는지는 아직 실제 클라이언트로 확인하지 못했다.
- 구현 도구는 **paperweight-userdev**로 정했다. 26.3 dev bundle(`26.3.build.246-stable`)이 Paper 저장소에 있고, NMS 클래스를 직접 써서 버전이 바뀌면 컴파일에서 깨진다. PacketEvents는 배포 저장소(CodeMC)에서 26.3 지원 여부를 확인할 수 없었고, 별도 플러그인이나 shade가 필요하다.

### 규칙

- 닉네임은 관리자가 정해 준다(`/nick <플레이어> <닉네임>`, 권한 `smputil.nick.others`). 본인 변경은 권한 `smputil.nick.self`로 열 수 있다(기본 OP).
- 다른 플레이어의 진짜 이름이나 닉네임과 같은 닉네임은 거절한다(대소문자 무시). 사칭을 막기 위해서다.
- 길이와 허용 문자는 설정으로 둔다. 기본: 1~16자, 한글·영문·숫자·밑줄.
- `/nick <플레이어> reset`으로 진짜 이름으로 되돌린다.

### 다른 플러그인과의 약속 (변경 금지)

닉네임은 플레이어 PDC의 아래 키에 문자열로 저장한다. **AdminUtil이 이 키를 직접 읽는다.** 코드 의존 없이 데이터로만 연결하기 위해서다.

| 항목 | 값 |
|---|---|
| 키 | `smputil:nickname` (`NamespacedKey("smputil", "nickname")`) |
| 타입 | `PersistentDataType.STRING` |
| 없음 | 키가 없으면 닉네임이 없는 것(진짜 이름 사용) |

- 플러그인 이름을 바꾸더라도 네임스페이스는 `smputil`로 고정한다. `NamespacedKey(plugin, ...)`이 아니라 문자열로 직접 만든다.
- 이 표를 바꾸면 AdminUtil DESIGN의 같은 표도 함께 바꾼다.

## 4. 집과 스폰

- `/sethome [이름]`, `/home [이름]`, `/delhome <이름>`. 이름을 생략하면 `home`.
- 한 사람당 집 개수 상한은 설정(기본 1). 옛 Utility는 1개였다.
- 옛 Utility는 관리자 토글로 켠 사람만 집을 쓸 수 있었다. 새로는 **서버 설정 하나로 켜고 끈다**(`home.enabled`, 기본 켜짐).
- `/spawn`: 개인 리스폰 지점(침대·리스폰 정박기)이 있으면 그곳, 없으면 월드 스폰. `/spawn world`는 항상 월드 스폰.
- 텔레포트는 `teleportAsync`.
- 텔레포트 대기 시간(움직이면 취소)은 설정으로 둔다. 기본 0초(즉시). 전투 중 도주용으로 쓰이는 게 문제가 되면 운영 중에 늘린다.

## 5. 텔레포트 요청 (tpa)

- `/tpa <플레이어>`: 요청자가 대상에게 간다.
- 대상에게 클릭할 수 있는 [수락] [거절] 메시지를 보낸다. `/tpaccept`, `/tpdeny`로도 처리한다.
- 요청은 15초 뒤 만료(설정). 만료·거절은 요청자에게 알린다.
- 한 대상에게 대기 중인 요청은 하나, 한 요청자가 보낸 대기 요청도 하나.
- 수락하는 순간 요청자가 오프라인이거나 다른 월드로 이동했어도, 수락 시점의 대상 위치로 보낸다.
- 요청 목록(누가 누구에게 언제)은 Bukkit과 분리한 순수 클래스로 만들어 단위 테스트한다. 만료 시각은 주입한 `Clock`으로 판정한다.

## 6. 거래

### 옛 구조의 문제

옛 Utility는 두 사람이 **같은 인벤토리 하나**를 함께 열고 `/trade finish`가 창만 닫았다.

- 양쪽이 동의했는지 확인하는 단계가 없어서, 상대가 물건을 넣었다 빼는 사기가 가능했다.
- 거래가 끝났을 때 창 안의 아이템이 누구에게 가는지 정해져 있지 않았다.

### 새 구조

- `/trade <플레이어>`로 요청하고, 상대가 수락하면 두 사람에게 같은 거래 화면이 열린다(요청 규칙은 tpa와 같다. 15초 만료).
- 화면은 **왼쪽 = 내 칸, 오른쪽 = 상대 칸**. 각자 자기 칸에만 넣고 뺄 수 있다. 상대 칸은 보기만 한다.
- 각자 [확인] 버튼이 있다. **어느 쪽 칸이든 내용이 바뀌면 두 사람의 확인이 모두 풀린다.** 넣었다 빼기 사기를 막는 핵심 규칙이다.
- **두 사람이 모두 확인한 순간** 한 번에 교환한다. 각자 상대 칸의 아이템을 받는다.
- 받을 공간이 부족하면 넘치는 아이템은 발밑에 떨군다. 교환 자체는 막지 않는다.
- 거래 거리 제한은 설정(기본 없음).

### 모든 종료 경로에서 아이템의 행방

| 상황 | 아이템 |
|---|---|
| 둘 다 확인 | 서로 교환 |
| 한쪽이 취소하거나 창을 닫음 | 각자 자기 칸의 아이템을 돌려받는다 |
| 한쪽 접속 종료 | 각자 자기 칸의 아이템을 돌려받는다. 나간 사람은 저장 전에 인벤토리로 |
| 한쪽 사망 | 죽은 사람의 칸은 그 자리에 떨군다(사망 드롭이 이미 정해진 뒤라 인벤토리에 넣으면 사라질 수 있다). 상대는 돌려받는다 |
| 서버 종료(플러그인 비활성화) | 닫힘 이벤트를 기다리지 않고 직접 각자에게 돌려준다 |

- 위 반환 경로들은 Econet의 판매 상자가 Paper 26.3 서버 코드로 확인한 순서와 같다(Econet CLAUDE.md "정부 매입" 참고).
- 거래 상태(칸 내용, 확인 여부, 종료 결과)는 Bukkit과 분리한 순수 클래스로 만들고, **"교환 전후로 아이템의 총합이 같다"**를 무작위 시나리오로 테스트한다.
- 거래 화면의 버튼·구분선 같은 UI 아이템에는 고유 태그를 단다. 플레이어의 같은 아이템이 그 칸에 합쳐지지 않게 하기 위해서다.

## 7. 도전과제 공유

- 켜져 있으면 접속 중인 모든 플레이어의 도전과제 진행 상황을 **합집합**으로 맞춘다. 협동 서버에서 "우리 서버가 달성한 것"이 되게 하기 위해서다.
- 켤 때, 플레이어가 접속할 때, 누군가 세부 조건을 달성할 때 맞춘다.
- `recipes/` 도전과제(레시피 해금)는 제외한다.
- 켜고 끄는 건 관리자만(`smputil.syncadv.toggle`). 상태는 저장해서 재시작해도 유지한다.

## 8. 접속자 목록

- 닉네임(진짜 이름), 핑을 보여 준다. 투명화된 플레이어는 볼 수 없는 사람에게는 뺀다.
- UUID 줄(클릭하면 복사)은 권한 `smputil.players.uuid`(기본 OP)가 있을 때만 보여 준다.

## 9. 제안

- `/suggest <내용>`: 서버에 바라는 것을 적어 보낸다. 누구나 쓴다(`smputil.suggest`, 기본 모두).
- 제안은 `suggestions.yml`에 번호(`#1`, `#2`…)와 함께 쌓이고, 설정한 디스코드 채널에 새 제안이 올라왔다고 알린다.
- 읽고 처리하는 일은 디스코드 채널과 파일로 한다. 게임 안 관리 명령(목록·삭제)은 관리자 기능이라 SMPUtil에 두지 않는다(1장).
- 도배 방지: 같은 사람은 `suggestion.cooldown-seconds`(기본 60초)가 지나야 다시 보낼 수 있다. 쿨다운은 저장된 제안 시각에서 계산해 재시작해도 이어진다. 길이 상한은 `suggestion.max-length`(기본 200자).
- 줄바꿈·연속 공백은 한 칸으로 줄여 저장한다.
- **디스코드 웹훅 주소는 비밀이다.** 주소를 아는 사람은 누구나 그 채널에 글을 쓸 수 있다.
  - 번들 `config.yml`은 비워 두고, 서버의 `plugins/SMPUtil/config.yml`에만 적는다. 틀린 주소는 시작 시 실패하되 **오류 메시지와 로그에 주소를 싣지 않는다.** 비우면 알림만 꺼진다.
  - `discord.com`/`discordapp.com`의 `/api/webhooks/` https 주소만 받는다. 설정 실수나 악용으로 서버가 임의 주소에 요청을 보내지 않게 하기 위해서다.
- 디스코드 전송은 비동기로 하고, 실패해도 제안은 이미 저장돼 있어 잃지 않는다. 실패는 상태 코드만 로그에 남긴다.
- 제안 내용에 `@everyone` 같은 것이 있어도 멘션이 되지 않게 `allowed_mentions`를 비운다.
- 보낸 사람 표시는 제안한 때의 `닉네임 (진짜 이름)`을 그대로 저장한다. 나중에 닉네임이 바뀌어도 기록은 그때의 것이다.

## 10. 옛 Utility에서 버린 것

| 기능 | 이유 |
|---|---|
| `/reload` | `Bukkit.reload()`는 Paper가 쓰지 말라고 하는 기능이다. 특히 Econet은 DB 쓰기 스레드와 코루틴을 쓰므로 리로드 중 장부 쓰기가 끊길 수 있다. 재시작으로 대신한다 |
| `AutoQuoteListener` | 진짜 이름을 한글로 바꾸던 옛 닉네임 방식의 우회책이었다. 새 방식에서는 필요 없다 |
| `/compass` | `/give`로 충분하다 |
| 관리자 기능 전부 | `AdminUtil`로 옮겼다 |

## 11. 미정 사항

- 텔레포트·구역 보호 비용 (Econet API가 생긴 뒤)
- 텔레포트 대기 시간과 거래 거리 제한의 운영값
